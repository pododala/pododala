# pododala 개인 위키: 프로젝트 구조와 운영 흐름

pododala 개인 위키는 Markdown으로 글을 작성하고, 같은 원고를 웹사이트와 AI 탐색 자료로 배포하는 개인 프로젝트다. 저장소는 [pododala/pododala](https://github.com/pododala/pododala), 웹사이트는 [pododala 열린 노트](https://pododala.github.io/pododala/)다. 기존 개인 위키의 코드와 원고를 출발점으로 삼되, 운영 저장소와 사이트 주소를 분리하여 개인 프로젝트로 운영한다.

프로젝트를 이해하는 핵심은 원고, 생성 데이터, 화면, 배포의 역할을 나누어 보는 데 있다. 글을 고치는 곳과 화면을 고치는 곳이 다르며, 자동으로 만들어지는 파일은 원본에서 다시 생성한다. 이 문서는 2026년 11월 2일의 실제 코드와 확인된 배포 상태를 기준으로 현재 구조를 설명한다.

## 프로젝트의 실행 방식

화면은 HTML, CSS, JavaScript로 구성된다. 브라우저가 `index.html`을 열고 `app.js`를 실행하면 `notes.json`을 읽어 문서 목록과 본문을 그린다. React 같은 별도 화면 프레임워크나 애플리케이션 서버, 데이터베이스 없이 정적 파일로 동작한다.

Node.js는 원고를 데이터와 정적 페이지로 변환하고 검증할 때 사용한다. GitHub Actions의 배포 환경은 Node.js 22를 사용하며, 현재 스크립트 실행에는 별도 npm 패키지 설치가 필요하지 않다. 글을 읽는 방문자가 Node.js를 설치할 필요도 없다.

AI와 함께 글을 편집하고 AI가 읽을 수 있는 색인을 제공하지만, 현재 사이트 자체에는 AI API를 호출하는 기능이 없다. 글 생성이나 질의응답을 자동으로 수행하는 서버가 연결된 구조는 아니다.

## 폴더와 파일의 역할

| 위치 | 역할 | 수정 기준 |
| --- | --- | --- |
| `index.html` | 사이트 진입 화면, 헤더·사이드바·푸터, 메타 정보 | 화면 뼈대나 사이트 안내를 바꿀 때 수정 |
| `style.css` | 문서·목록·모바일 화면 등의 디자인 | 색상, 간격, 배치 등을 바꿀 때 수정 |
| `app.js` | 검색, 주제 필터, 주소 해석, Markdown 표시, 관련 문서 | 탐색과 문서 표시 기능을 바꿀 때 수정 |
| `calendar.js` | 연대와 절기로 문서를 찾는 데스크톱 달력 | 달력의 표시와 상호작용을 바꿀 때 수정 |
| `wiki/` | Markdown 원고와 메타데이터·관계·달력 원본 | 새 글 작성과 내용 관리의 중심 |
| `scripts/` | 생성·검증·검색 스크립트 | 데이터 처리와 검증 방식을 바꿀 때 수정 |
| `editorial/` | 편집 장부, 교차 연결 제안, 정비 기록과 생성 지도 | 편집 이력을 기록하고 필요한 원고를 탐색 |
| `ai/` | 공개 문서의 기계용 색인과 관계 데이터 | 생성 스크립트로 갱신 |
| `.github/workflows/` | 자동 검증과 GitHub Pages 배포 | 빌드와 게시 흐름을 바꿀 때 수정 |
| `sources/` | 기존 자료 파일 | 원고·사이트 데이터와 구분하여 유지 여부 검토 |
| `README.md` | 저장소 사용과 운영 안내 | 프로젝트 설정과 사용법 변경 시 갱신 |
| `PERSONALIZATION.md` | 개인화한 위치와 남은 설정 목록 | 사이트 이름·주소·외부 연결 변경 시 참고 |

## 원고와 메타데이터를 관리하는 구조

글 본문의 원본은 `wiki/<문서-id>.md`다. 첫 줄에 `# 제목`을 쓰고 한 줄을 비운 뒤 본문을 작성한다. 사이트의 자체 렌더러는 단락, `##`부터 `####`까지의 소제목, 목록, 강조, 인라인 코드, 링크, 표를 지원한다. 일반 Markdown 편집기에서 가능한 모든 문법이 구현된 것은 아니므로, 본문은 이 범위 안에서 작성하는 편이 맞다.

문서의 제목, 분류, 요약, 태그, 공개 여부와 관련 문서는 `wiki/manifest.json`의 `documents`에 등록한다. 문서 ID는 소문자 영문·숫자·하이픈으로 지정하며, 파일 경로와 문서 ID가 대응한다. 사이트의 주제 목록은 공개 문서의 `category`를 바탕으로 만들어진다. 따라서 새 분류를 가진 문서를 등록하면 별도의 메뉴 코드를 추가하지 않고도 그 주제가 나타난다. 이 글의 분류는 **프로젝트**다.

대표적인 필드는 다음과 같다.

| 필드 | 의미 |
| --- | --- |
| `id`, `path` | 문서 식별자와 원고 파일 경로 |
| `title`, `summary`, `tags` | 제목, 요약, 검색과 탐색에 쓰는 태그 |
| `category` | 사이트 주제 분류 |
| `publish` | 사이트와 공개 색인에 포함할지 결정 |
| `related` | 관련 문서의 ID 목록 |
| `aliases` | 편집 탐색용 별칭 |
| `order` | 생성 데이터의 정렬 기준 |
| `updated` | 문서 수정일 |
| `last_enriched_on` | 실제 지식을 증보한 날 |
| `source`, `status`, `review_state` | 근거와 검토 범위·상태 |

문서 사이의 의미를 설명하는 관계는 `wiki/relations.json`, 달력에 표시할 날짜와 문서의 연결은 `wiki/calendar.json`이 원본이다. 단순한 관련 문서 목록과, 근거 절·관계 유형을 명시한 의미 관계는 구분하여 관리한다.

## 원본에서 만들어지는 생성물

`scripts/build-notes.mjs`는 Markdown과 manifest를 읽어 `notes.json`을 만든다. 이 파일에는 공개 문서의 메타데이터와 본문이 들어 있다. 브라우저는 이 데이터를 한 번 읽고 검색·필터·본문 표시를 수행한다. 사이트에서 보이는 내용을 바꾸려면 원고나 manifest를 수정해야 한다. `notes.json`만 고치면 다음 생성 때 원본 내용으로 다시 바뀐다.

`scripts/build-ai-index.mjs`는 `AI_INDEX.md`, `ai/index.json`, `ai/relations.json`, `llms.txt`를 생성한다. 공개 문서의 목록, 원본 Markdown 주소, 정적 문서 주소와 관계 정보를 외부 도구가 찾을 수 있도록 제공하는 자료다.

`scripts/build-wiki-map.mjs`는 `editorial/map/` 아래에 전체 지도, 문서별 카드, 지식 표제 역색인을 생성한다. 이 지도는 미게시 원고도 포함하여 편집할 내용을 찾는 데 사용한다. `scripts/build-maintenance-queue.mjs`는 원고와 기록을 살펴 정비 대기열을 만든다. 공개 탐색 색인과 편집용 지도는 포함 범위와 용도가 다르다.

편집 장부의 원본인 `editorial/ingestions/`에는 반영한 지식의 짧은 표제와 실제 문서·절을 기록한다. 대화 원문을 복제하는 공간이 아니다. 생성된 지도와 대기열도 직접 편집하지 않고 원고·메타데이터·장부에서 갱신한다.

## 웹 화면과 두 종류의 문서 주소

웹사이트의 기본 경로는 `/pododala/`다. 첫 화면은 문서 탐색 화면이며, `#all`은 전체 문서와 검색, `#about`은 소개, `#calendar`는 달력, `#<문서-id>`는 해당 문서에 대응한다. 이 글은 [프로젝트 구조 문서](https://pododala.github.io/pododala/#pododala-project-structure) 주소로 찾을 수 있다.

탐색 화면의 본문은 JavaScript가 표시한다. 한편 `scripts/build-static.mjs`는 배포할 때 각 글의 본문이 이미 들어 있는 `notes/<문서-id>/index.html`을 만든다. 예를 들어 이 글의 [정적 문서 페이지](https://pododala.github.io/pododala/notes/pododala-project-structure/)는 JavaScript로 본문을 조립하지 않아도 읽을 수 있다. 정적 생성기는 `app.js`의 문서 렌더러를 실행하여 두 화면의 본문 표시를 공유한다.

정적 문서 목록인 `notes/index.html`과 검색엔진용 `sitemap.xml`도 배포 때 생성한다. 이 결과물은 원고와 달리 저장소에 직접 커밋하지 않는다. CSS, 메뉴, 문서 링크는 `/pododala/` 하위 경로를 사용하도록 설정되어 있다. 저장소 이름이나 사이트 도메인이 바뀌면 이 경로도 함께 검토해야 한다.

## 작성에서 배포까지의 흐름

1. `wiki/<문서-id>.md`에 새 글을 작성하거나 기존 원고를 수정한다.
2. `wiki/manifest.json`에 문서를 등록하고 분류·요약·공개 여부·관련 문서를 지정한다.
3. 신규 지식을 반영했다면 편집 장부에 문서와 정확한 절을 기록한다.
4. 로컬에서 생성·검증 스크립트를 실행하여 누락된 문서와 깨진 연결을 확인한다.
5. 원고·메타데이터·장부를 `pododala/pododala`의 `main` 브랜치에 커밋하고 업로드한다.
6. GitHub Actions가 사이트 데이터, AI 색인, 편집 지도와 정비 대기열을 생성하고 검증한다.
7. 생성물을 저장소에 자동 커밋한 뒤 정적 페이지와 사이트맵을 포함한 배포 파일을 만든다.
8. GitHub Pages가 결과물을 게시한다. 검증이나 배포가 실패하면 실행 기록에서 실패 지점을 확인한다.

주 배포 정의는 `.github/workflows/deploy-pages.yml`이다. `main` 업로드 또는 수동 실행으로 시작한다. `.github/workflows/validate-notes.yml`은 다른 브랜치와 PR의 관련 변경을 검증한다. GitHub Pages의 배포 소스는 GitHub Actions로 설정되어 있다.

로컬 기본 확인 명령은 `node scripts/build-notes.mjs`, `node scripts/build-ai-index.mjs`, `node scripts/build-wiki-map.mjs`, `node scripts/build-maintenance-queue.mjs`다. 생성 뒤 각 스크립트의 `--check`와 편집 기록·연결·달력 검증, 뷰어 테스트로 형식과 동작을 확인한다. 코드가 저장소에 올라간 상태와 웹사이트에 게시된 상태는 별도이므로 마지막으로 Actions 실행 결과와 실제 페이지 응답을 확인한다.

## 개인 프로젝트로 운영할 때의 변경 지점

현재 운영 저장소는 `pododala/pododala`이며 기존 원본 저장소와 별개다. 헤더·푸터의 이름, 원문·편집·이력 링크, 정적 페이지 작성자, AI 색인의 주소는 현재 저장소와 사이트를 사용한다. 현재 사이트에는 프로젝트 구조 문서만 남기고 이전 원고와 관련 편집 기록을 삭제했다. 삭제 전 자료는 Git 커밋 이력에서 확인할 수 있다.

댓글은 giscus 연결 코드를 갖고 있지만 `app.js`의 `comments.repoId`와 `comments.categoryId`가 비어 있어 현재 꺼져 있다. 사용할 경우 본인 저장소에 연결된 값을 입력해야 한다. 기존 Google·네이버 사이트 소유권 확인 값은 제거된 상태이며, 다시 등록할 때는 본인 값을 사용한다.

프로젝트 이름·도메인·저장소를 바꿀 때는 `index.html`, `app.js`, `scripts/build-static.mjs`, `scripts/build-ai-index.mjs`, `scripts/search-wiki.mjs`, `robots.txt`와 링크를 검증하는 테스트를 함께 확인한다. `scripts/build-notes.mjs`의 이전 도메인 처리는 기존 원고 링크를 내부 문서 링크로 바꾸는 호환 로직이다.

`publish: false`는 사이트 목록과 공개 색인에서 글을 제외하는 설정이다. 저장소 자체는 Public이며 배포 구성도 원고와 편집 파일을 포함하므로, 이 값이 파일을 비공개로 보호하지는 않는다. 공개 원고에 비밀 값이나 개인 대화 원문을 넣지 않는 운영 기준이 필요하다.

## 달력 동작 예시

달력의 연대 표시를 확인하기 위해 **1986년 작성자 탄생**을 예시로 등록했다. 실제 작성자의 출생 정보를 확인한 기록이 아니라 기능 확인용 가상 항목이다. 월과 일은 지정하지 않고 1986년 한 해에 연결한다.

데스크톱 화면에서 [달력 열기](https://pododala.github.io/pododala/#calendar)를 선택하면 연대 탭에 1986년과 ‘작성자 탄생 (예시)’이 표시된다. 세기·10년·1년 단위로 바꾸어 같은 항목의 위치를 확인할 수 있다. 항목이나 해당 연대 칸에 마우스를 올리면 연결된 표시가 강조되고, 목록의 항목을 누르면 이 절로 이동한다. 연도만 등록한 항목이므로 절기 탭에는 나타나지 않는다.

달력 데이터는 `wiki/calendar.json`의 `c001` 항목이다. 표시 문구는 `label`, 연도는 `from`, 연결할 문서는 `doc`, 이동할 절의 제목은 `section`에 지정한다. 현재 달력 화면은 가로 900px 이상에서 표시된다.

## 확인 범위와 현재 콘텐츠

설명 범위는 현재 저장소의 코드, 생성·검증 스크립트, 워크플로와 2026년 11월 2일에 확인한 실제 배포 결과다. 향후 AI API, 로그인, 데이터베이스, 관리 화면을 도입한다면 현재와 다른 구성 요소가 추가된다. 이들은 현재 구현된 기능에 포함하지 않는다.

현재 공개 주제는 프로젝트 하나이며, 이 문서가 첫 원고다. 앞으로 새 프로젝트 기록을 추가할 때 Markdown 파일과 manifest를 함께 등록한다. 이전 원고를 가리키던 연결과 편집 기록은 정리했으며, 달력에는 위의 기능 확인용 예시만 등록되어 있다.
